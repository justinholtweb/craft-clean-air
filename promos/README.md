# Plugin Store promo images

Marketing images for the Clean Air listing on the Craft Plugin Store, rendered in the same theme as
the plugin's marketing page at
[justinholt.com/plugins/craft-cleanair](https://justinholt.com/plugins/craft-cleanair).

## Building

```bash
./build.sh          # all slides
./build.sh "2 5"    # just slides 2 and 5
```

Output lands in `out/` as `cleanair-promo-N.jpg`, 1920×1080 (rendered at 2× in headless Chrome, then
downsampled and converted to JPEG so the type stays crisp and the files stay small).

## Screenshots

`shots/` holds real control-panel captures, not mockups. They were taken against
`~/Sites/plugin-testing` with Clean Air on the Pro edition, cropped to `#content` so no global
sidebar or other plugin's UI appears. Two things are adjusted before the capture, both to make the
shot representative rather than flattering:

- The element-type tab row is trimmed to the stock Craft + Commerce set. The test rig has ~40
  plugins installed and renders 58 tabs, which no real site does.
- Other plugins' floating panels (Queuebert's bar, Puppy, Yo) are hidden.

`ul.pane-tabs` carries `margin-left: -24px` to bleed to the pane edge, so the capture needs at least
that much left padding on `#content` or the active tab is clipped.

## Editing

Everything lives in `slides.html` — one `<section class="slide">` per image. The palette is the
plugin site's: accent `#2E8F77`, light accent `#5FBFA6`, both derived from the app icon's teal.
Jersey 20 for display, Inter for body.

`assets/` holds the fonts and two icon files:

- `icon.svg` — the app icon, used for the cover mark and the footer lockup. Copy it from
  `../src/icon.svg` whenever the icon changes.
- `watermark.svg` — the tree silhouette with the rounded frame stripped, which is exactly
  `../src/icon-mask.svg`. The full icon's frame reads as a hard-edged box at watermark scale, which
  is why the frame is dropped rather than the whole icon being faded further.

`fonts.css` is generated by `build.sh` (the woff2 files are base64-inlined so Chrome's `file://`
origin rules can't block them) and is not checked in.
